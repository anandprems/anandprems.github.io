Semi-Structured Data — JSON, XML and Where They're Used

Not all data fits neatly into tables. Not all data is completely unstructured either. There is something in between — and it powers much of the modern internet.

Introduction: How Do Applications Share Information?

You browse the menu, select your favourite dish, enter your delivery address, and tap Place Order.

How do all these radically different platforms exchange information without friction?

They need a neutral, universal language to represent and communicate data.

This is where Semi-Structured Data becomes indispensable.

Two prominent standards power this global exchange: JSON (JavaScript Object Notation) and XML (Extensible Markup Language).

1. What Is Semi-Structured Data?

Semi-structured data is information that does not conform to the rigid schema of a traditional relational database (rows and columns), but still contains internal tags, keys, or markers that separate data elements and enforce hierarchical relationships.

In simple words:

It is data that possesses self-describing organization, without being locked into rigid, fixed table columns.

Consider this simple student record:

student.json 
{
  "student_id": 101,
  "name": "Arun",
  "age": 20,
  "department": "Computer Science"
}

Notice what makes this format so elegant:

  • There are no predefined table rows or pre-allocated column memory spaces.
  • Every piece of information is self-describing through Keys ("name", "age") and Values ("Arun", 20).
  • It is human-readable as well as lightweight for computers to parse.

Imagine designing an e-commerce catalog for an online marketplace like Amazon.

Every product shares some common baseline traits (Product ID, Name, Price, Brand, Availability). But once you look closer, different product categories have completely incompatible specifications:

The Relational Database Dilemma: In a strict tabular database (SQL), if you tried to put both products into one table, the book row would have empty NULL values for screen size, RAM, and battery, while the smartphone row would have NULL for author and ISBN. Over hundreds of categories (clothing, medicines, furniture), tables quickly become bloated with dozens of empty columns!

The Semi-Structured Solution: With JSON, each product record carries only the specific attributes relevant to itself. This schema flexibility is the primary reason JSON and document databases (like MongoDB) are ubiquitous across modern tech platforms.

3. What Is JSON?

JSON stands for JavaScript Object Notation. It is a lightweight, language-independent, text-based data interchange format.

Despite originating from JavaScript, JSON is natively supported by virtually every major programming language today, including Python, C++, Java, Rust, and Go.

JSON with Arrays: Representing Collections

When an application needs to send a collection of multiple records, it nests objects inside a square-bracket array [ ]:

students_list.json 
{
  "students": [
    { "id": 101, "name": "Arun", "gpa": 8.5 },
    { "id": 102, "name": "Priya", "gpa": 9.2 },
    { "id": 103, "name": "Kavin", "gpa": 7.8 }
  ]
}

Here, the single key "students" maps to an array containing three discrete student objects. This hierarchical nesting makes JSON extraordinarily capable of representing real-world nested structures (such as an order containing multiple line items).

4. What Is XML?

XML stands for Extensible Markup Language. Published by the W3C in 1998, it was designed to store, structure, and transport data across different systems.

Unlike JSON, which mirrors programming language objects, XML is a markup language. It uses custom opening and closing tags (similar to HTML) to enclose data.

Here is how the exact same student record looks in XML:

student.xml 
<student>
    <name>Priya</name>
    <age>21</age>
    <department>IT</department>
    <is_student>true</is_student>
</student>

Understanding the XML architecture:

  • <student> is the root element that wraps the entire record.
  • Every opened tag (e.g., <name>) must have a corresponding closing tag (</name>).
  • Elements can be nested to form deep hierarchical trees.

XML with Attributes

A unique superpower of XML is its ability to attach metadata attributes directly inside the opening tag:

students_attributes.xml 
<students university="VIT Chennai" year="2026">
    <student id="101" status="active">
        <name>Arun</name>
        <department>CSE</department>
    </student>
    <student id="102" status="graduated">
        <name>Priya</name>
        <department>ECE</department>
    </student>
</students>

Here, id="101" and status="active" provide descriptive metadata about the entity without requiring child elements.

A Vital Clarification:

Neither JSON nor XML is a database by itself. They are data serialization and transmission standards — formats designed to transport structured data through wires, APIs, and storage files.

1. Web Applications & RESTful APIs

When you log in to an educational portal or social media network, your client browser submits credentials and receives a JSON web token (JWT) verifying your identity. Almost all modern public APIs (Stripe, GitHub, Google Maps) speak fluent JSON.

2. Software Configuration Files

Modern developer environments and runtime engines rely heavily on semi-structured files for project configuration:

  • package.json in Node.js ecosystems
  • settings.json in VS Code
  • pom.xml in Java Maven architectures
  • AndroidManifest.xml in Android mobile operating systems

3. Enterprise Document Exchange & Banking (XML)

While JSON conquered web and mobile development, XML remains the backbone of enterprise and mission-critical financial systems:

  • SWIFT and ISO 20022: Global interbank financial messaging standards for wire transfers and transactions.
  • Microsoft Office & OpenDocument: Every modern .docx, .xlsx, and .pptx file is actually a zipped archive of XML documents under the hood!
  • Healthcare Standards: HL7 (Health Level Seven) clinical document architectures for exchanging patient charts between hospitals.

7. How Do Applications Process JSON and XML?

Transmitting data is only half the battle. Once an application receives a raw JSON or XML string over the network, it must read, validate, and convert it into memory objects that code can work with.

This conversion process is called Parsing.

python_parsing_demo.py 
# How Python parses semi-structured JSON
import json

raw_json = '{"name": "Priya", "age": 21, "department": "IT"}'

# Convert JSON string to Python dictionary
student = json.loads(raw_json)

print(student["name"])        # Output: Priya
print(student["department"])  # Output: IT

Common parsing models across industries include:

  • DOM (Document Object Model): Loads the entire XML or JSON file into memory as a navigable hierarchical tree. Fast and flexible, but memory-intensive for massive files.
  • SAX / StAX (Streaming Parsers): Reads XML sequentially event-by-event. Ideal for processing multi-gigabyte files with minimal RAM footprint.
  • JSON Native Parsers: Ultra-fast C-backed serialization libraries built natively into V8, Python, and modern language runtimes (e.g., JSON.parse()).

8. The Big Picture: Connecting the Three Data Types

Over our data series, we have explored Structured Data (tables, databases), Unstructured Data (images, audio, biosignals), and now Semi-Structured Data (JSON, XML).

How do they fit together in real engineering systems? A modern enterprise uses all three simultaneously:

Think of an e-commerce platform like Amazon:

  • Your credit card payment and order ID are committed into a strict Structured SQL relational database.
  • The product specifications, search filter parameters, and mobile API communications flow via Semi-Structured JSON.
  • The high-resolution product unboxing photos and video reviews are stored in an Unstructured Object Lake (like AWS S3) and analyzed by AI Computer Vision models.

9. Key Takeaways

Let's summarize the foundational takeaways from today's deep dive:

  1. The Golden Middle: Semi-structured data bridges rigid SQL tables and raw unstructured media, offering flexible, self-describing schemas.
  2. JSON Simplicity: Uses lightweight key-value pairs, objects { }, and arrays [ ]. It is the undisputed lingua franca of the modern web and REST APIs.
  3. XML Power: Uses hierarchical opening and closing tags with metadata attributes. It remains indispensable in enterprise integration, financial standards (ISO 20022), and office document architectures.
  4. Format vs. Storage: Neither JSON nor XML is a database; they are textual representation and serialization standards parsed by programs.
  5. The Complete Triad: Mastering data engineering requires understanding how structured, semi-structured, and unstructured formats collaborate within modern software pipelines.
